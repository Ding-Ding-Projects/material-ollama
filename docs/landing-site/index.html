Operations

Every route carries its inputs, output, progress, cancellation, and error state.

  • ✓ Run and stop model sessions
  • ✓ Pull, push, copy, create, show, and delete
  • ✓ Serve and inspect the local service
  • ✓ Discover hardware and runner details
  • ✓ Search, export, and revisit operation history
⚙

Configuration

Profiles explain effective values and never silently rewrite an external service.

  • ✓ Browse supported environment settings
  • ✓ See the value source and precedence
  • ✓ Apply a managed profile with explicit restart
  • ✓ Export, restore, and record local changes
  • ✓ Keep unsupported values visible with a reason
!
Configuration scope matters

A GUI-owned profile applies only to the service instance that Material Ollama manages. An unrelated service stays untouched and remains visible as external state.

Article · orientation

The landing page is the map, not the machine.

Use this surface to understand the desktop product, read its documentation, see its current release state, and find a verified download when one exists. Model execution, local service control, and user data remain inside the installed application.

That distinction is intentional. A landing page can be available when the local service is stopped, while the runtime must give the user precise service and model state. Keeping the two roles separate makes both surfaces easier to trust.
