# Local suite inventory

This is the hand-written contract for every local test/verification **suite area** the release
gate cares about — not a description of what happens to already be running, but a fixed list of
what MUST have a row, checked against the real repository by
[`scripts/check-suite-inventory.mjs`](../../../scripts/check-suite-inventory.mjs). A suite area
omitted from the table below fails that gate; a row whose `covered`/`partial` evidence does not
actually resolve on disk fails it too. There is no mechanism by which this document can silently
shrink to match whatever suites happen to exist — the checker's own required-area list is
hand-written and independent of this file's contents (see that script's `REQUIRED_AREA_IDS`).

**Most rows below are `missing`, and that is the correct, useful answer.** A `missing` status is
not a defect in this document; it is an honest report that no dedicated suite exists yet for that
area, together with the real reason and (where one exists) a pointer at the real, untested
implementation. Inflating a row to `covered` because *something* nearby has a test would make this
document actively misleading, which is worse than an honest gap.

## Status vocabulary

- **`covered`** — a real, committed suite exists for this area, its evidence resolves against the
  real filesystem (an exact test declaration or a real script), and it was run and observed passing
  this session.
- **`partial`** — real evidence exists and resolves, but it covers only part of the area (a narrow
  scenario, one branch of several, a rendering-safety slice of a bigger feature) or the underlying
  check is currently failing for reasons outside this lane's scope. The `Notes` column says exactly
  what is and is not covered.
- **`missing`** — no dedicated suite exists for this area at all. `Command` and `Evidence` both
  carry the literal placeholder `—`, and `Notes` carries the real reason (and, where one exists, the
  real untested implementation to point a future lane at).

## Checks

The structural check (every required area present exactly once; every `covered`/`partial` row's
evidence resolves; every `missing` row carries a real reason) runs with:

```
node scripts/check-suite-inventory.mjs
```

The negative-regression self-test mutates one row (or the table itself) at a time — a required area
removed, a duplicate or unrecognized area id, an invalid status, a `missing` row that keeps a real
command or evidence claim, a `missing`/`partial` row whose reason is too short to be real, a
`covered` row with an empty command or a placeholder evidence claim, a malformed evidence string, an
evidence path that escapes the repository, an evidence path that does not exist, a claimed test
renamed to a superstring of itself, and a claimed test whose line still exists but is commented out
— and requires every one of those mutations to turn the checker red with its own exact guard code,
then requires the checker to go green again once the fixture is restored:

```
node scripts/check-suite-inventory.mjs --self-test
```

Both are wired into the root `package.json` as `npm run verify:suites`.
